# Архитектура Health-Bot-AI

## 1. Обзор

Health-Bot-AI — B2B-ассистент менеджера продаж. Система принимает контекст
сделки и сообщение клиента, анонимизирует ПДн, формирует промпт по базе знаний,
вызывает LLM и возвращает два независимых блока:

1. `client_answer` — ответ, который можно отправить клиенту;
2. `manager_tip` — внутренняя подсказка по допродаже.

Дополнительно возвращаются `needs_upsell`, `citations`, `safety_flags`,
`request_id` и метаданные провайдера.

## 3. Слои

| Слой | Модули | Ответственность |
|---|---|---|
| Presentation | `app.py`, `src/ui/*` | Ввод, отображение, история, копирование |
| API | `src/api/webhook.py` | HTTP, валидация, auth, rate limit, SSE |
| Application | `src/services/*` | Сценарии, оркестрация, кэш, аудит |
| Domain | `src/core/*` | Анонимизация, парсинг, безопасность, БЗ |
| Integrations | `src/ai/*` | Провайдеры LLM, fallback, streaming |
| Config | `config/*` | Настройки, промпты, версии |
| Persistence | `src/core/db.py`, `repositories.py` | Аудит, обратная связь, БЗ |

## 4. Поток запроса

1. Клиент отправляет `POST /v1/consult` с `crm_context` и `client_message`.
2. API проверяет API-ключ, rate limit и идемпотентность.
3. `ConsultationService` анонимизирует оба поля.
4. `SafetyGuard` проверяет вход на prompt injection и red flags.
5. `KnowledgeBase` выбирает релевантные чанки и формирует контекст.
6. `PromptBuilder` собирает системный и пользовательский промпты.
7. `ResponseCache` ищет ответ по версионированному ключу.
8. `AIOrchestrator` вызывает провайдера; при необходимости — fallback.
9. `ResponseParser` разбирает JSON/два блока.
10. `SafetyGuard` проверяет выход, добавляет дисклеймер и флаги.
11. Событие пишется в аудит; ответ возвращается клиенту.

## 5. Хранилища

| Хранилище | Назначение | MVP | Production |
|---|---|---|---|
| SQLite | Аудит, обратная связь, локальная разработка | Да | Нет |
| PostgreSQL | Аудит, обратная связь, версии БЗ, пользователи | Опционально | Да |
| Redis | Кэш ответов, rate limit, идемпотентность | Опционально | Да |
| Файлы | `knowledge_base.txt`, версии БЗ | Да | S3/MinIO |

Строка подключения задаётся `DATABASE_URL`; по умолчанию
`sqlite:///data/health_bot.db`. Для PostgreSQL:
`postgresql+psycopg://user:pass@host:5432/health_bot`.

Схема создаётся через `Base.metadata.create_all` на старте. Для промышленного
контура рекомендуется добавить Alembic-миграции и отдельный job для миграций
до запуска приложения.

## 6. Безопасность

- ПДн анонимизируются до вызова LLM.
- В аудит пишутся только метаданные и количество ПДн по категориям.
- API защищён `X-API-Key`; административные операции — `X-Admin-Key`.
- Rate limit: in-memory для MVP, Redis для multi-worker.
- Идемпотентность: `Idempotency-Key` с TTL.
- Секреты — только через переменные окружения / Vault.
- Медицинские guardrails: дисклеймер, red flags, запрещённые утверждения.

## 7. Расширение

- Новый LLM-провайдер: реализовать `AIClient`, добавить в `PROVIDER_REGISTRY`.
- Новый тип ПДн: добавить распознаватель в `PIIAnonymizer`.
- Новая проверка безопасности: добавить правило в `SafetyGuard`.
- Переход на pgvector: заменить лексический retriever на embedding-retriever,
  сохранив интерфейс `KnowledgeBase.retrieve()`.
- Переход на Redis: задать `REDIS_URL`; фабрика кэша выберет Redis-бэкенд.
